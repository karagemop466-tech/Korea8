### R-04 — Two GitHub Actions workflows, only one runs automatically

| Workflow | Trigger | Installs deps? | Test pattern |
|---|---|---|---|
| `.github/workflows/overflow-pages.yml` | `push: [main]`, `workflow_dispatch` | **no** | `-p 'test_overflow*.py'` (18 tests) |
| `.github/workflows/gems-pipeline.yml` | `workflow_dispatch` **only** | yes (`pip install -r requirements.txt`) | `python -m pytest -q` |

Two consequences:

1. The geothermal pipeline never runs on push, so its evidence is not continuously regenerated. That
   is consistent with it being archived.
2. `gems-pipeline.yml` pushes to a **hardcoded branch**: `git push origin HEAD:arena/d7026453-korea8`.
   A stale session branch name is baked into a workflow on `main`. If that workflow is ever
   dispatched it will push to a branch belonging to a session that ended on 2026-11-04. This is a
   live cross-session hazard and should be parameterised or removed.

### R-05 — Full test discovery fails locally; this is an environment gap, not a code defect

`python3 -m unittest discover -s tests` → `Ran 20 tests … FAILED (errors=2)`. Both errors are
`ModuleNotFoundError: No module named 'numpy'` at import of `tests/test_metric.py` and
`tests/test_uniqueness_gate.py`.

Recorded accurately rather than over-claimed: `numpy>=1.26` is declared in `requirements.txt`, this
sandbox has no numpy and `pip install` is blocked by PEP 668 (externally-managed environment), so the
import cannot be satisfied here. Both modules belong to the archived geothermal project and are
excluded from CI by the `-p 'test_overflow*.py'` pattern. The 18 bathtub tests are
dependency-free and pass. **This is not a defect in the bathtub deliverable.** The residual risk is
only that the CI pattern means a future break in the geothermal tests would go unnoticed — which is
acceptable while that project is archived, and is noted so nobody reads "CI green" as "all tests
green".
